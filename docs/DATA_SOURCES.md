# Data Sources — SETU (SIH 2026, IHSIH027)

Every number this system produces traces back to one of the rows below. Each row states
whether the underlying data is **REAL** (an actual third-party observation), **DERIVED**
(computed from real data via a documented, non-trivial transformation), **SYNTHETIC**
(procedurally generated for this prototype, not a real record), or **SIMULATED** (mechanics
are real — e.g. a real blockchain transaction — but the environment/network is a local
development stand-in, not production infrastructure).

This file is also served machine-readably at `GET /api/data-sources` (see
`backend/app/db/init_db.py::DATA_SOURCE_REGISTRY`, which is the single source of truth this
document mirrors) so the frontend can render provenance badges next to any number.

## REAL

| Source | What it provides | Access | Limitations |
|---|---|---|---|
| **Open-Meteo Forecast API** (`api.open-meteo.com`) | Live hourly precipitation + soil moisture, daily precipitation sum, for any lat/lon | Free, no key, no signup | Global reanalysis/forecast model grid (~1-11km), not an IMD ground station reading — a documented proxy, not an IMD-equivalent observation |
| **Open-Meteo Archive API** (`archive-api.open-meteo.com`) | Historical daily rainfall back to ~1940 | Free, no key | Used to train the baseline risk model (`backend/app/ml/train.py`) |
| **USGS Earthquake Catalog** | Live seismic events, filtered to an India bounding box | Free, no key | Multi-hazard situational awareness only — not used by the flood model |
| **GDACS RSS feed** | Global multi-hazard alerts (floods/cyclones/quakes), severity-rated | Free, public feed | Raw XML, not parsed into structured fields in this build |
| **Hardhat local blockchain transactions** | Real Solidity contract execution, real tx hashes, real event logs | N/A — local dev chain | See SIMULATED note below: mechanics are real, network is local-only |

Verified reachable from this build environment on 2026-08-28 (see session log): Open-Meteo,
USGS, and GDACS all returned HTTP 200 to direct connectivity checks.

## DERIVED

| Source | Derivation | Limitations |
|---|---|---|
| **District population/vulnerability** (`data/districts_sample.json`) | Population figures referenced from public 2011 Census district summaries; `vulnerability_index` is a hand-set placeholder (0-1), not a sourced statistic | District-level only, not WorldPop-grid or village/ward level. Stand-in for the WorldPop + OSM overlay pipeline described in `ARCHITECTURE.md` — replace before any real deployment claim |
| **Flood-risk training label** (`app/ml/train.py`) | `high_risk = 1` if a day's 3-day rolling rainfall exceeds the 90th percentile of the pulled historical window | NOT a historical flood-occurrence record — see `MODEL_CARD.md` for why this is a documented proxy, not ground truth |
| **ESTIMATED POPULATION EXPOSED** (`gis_impact.assess_impact`) | `population × risk_score × vulnerability_index`, capped at 100% | A transparent formula, not a census count — always labeled "ESTIMATED" |
| **Relief requirement (gross/net)** (`requirement_engine.py`) | Population × per-capita/per-household norms (rules of thumb, see `relief_estimator.py` docstring), minus existing inventory | Per-capita coefficients are rounded rules of thumb, not sourced from an official Sphere/NDMA/SDRF table in this build — see `LIMITATIONS.md` |
| **Priority score** (`priority_engine.py`) | Weighted sum of severity/population/deficit/urgency/accessibility (Section 18 formula) | Weights are documented ASSUMPTIONS, configurable via `app/core/config.py` |
| **Allocation recommendation** (`allocation_engine.py`) | OR-Tools LP (or greedy fallback) over real DB inventory, distance (haversine), and ASSUMPTION accessibility scores | Accessibility scores are manually assigned per warehouse (no live road-closure feed) — see `LIMITATIONS.md` |

## SYNTHETIC

| Source | What it is | Never present as |
|---|---|---|
| Organizations, users, warehouses, inventory (`scripts/seed_demo.py`) | Procedurally seeded demo accounts and stock levels | Real government, NGO, or warehouse records |
| Allocations, dispatches, deliveries, the one intentional discrepancy (`scripts/run_demo_scenario.py`) | Generated by actually calling the real API in sequence | Real historical relief operations |

All of the above is labeled **SYNTHETIC PROTOTYPE OPERATIONAL DATA** everywhere it appears.

## SIMULATED

| Source | What's real vs. simulated |
|---|---|
| Local Hardhat blockchain (`blockchain/`) | The contract, transactions, hashes, and event log are genuinely real blockchain mechanics — this is not mocked. What's simulated is the network itself: a single local development chain, not a multi-organization consortium network with independent nodes run by District Admin/NGO/Warehouse orgs. See `BLOCKCHAIN.md`. |

## Datasets referenced in the project's planning documents but NOT YET integrated in code

The masterplan and frozen spec (`docs/SETU_SIH_Technical_Masterplan.md`,
`docs/SETU_Frozen_Implementation_Spec.md`) name CWC gauge data (Kampur/Dharamtul), IMD
gridded rainfall, Sentinel-1 SAR flood-extent labels, Copernicus DEM, and WorldPop as the
target production data stack for the Nagaon/Kopili basin. **None of these are wired into
the running code in this build** — they require registrations (Google Earth Engine, Copernicus)
or scraping infrastructure not built yet. The current build substitutes Open-Meteo
(rainfall proxy) and the hand-compiled district sample (population/vulnerability proxy),
both clearly labeled above. This substitution — not a silent one — is the single most
important thing to say honestly to a judge who asks "is this the real CWC/Sentinel-1 data
your PPT describes?" The answer is no, not yet; see `LIMITATIONS.md` and `JUDGE_QA.md` Q29.
